# Agent job charges are refunded once, when a failed job is read

An agent run is charged when it starts. If the engine refuses the job, `withCredits` refunds at once. A job the engine accepts can still fail later (a crew error, the 180s timeout), so the web app records each charge in `AgentJobCharge`, keyed by the engine's job id. The first read of a job whose status is `failed` claims that row by setting `refundedAt` and grants the credits back in the same transaction, so racing reads refund exactly once. We refund on read, rather than having the engine call back, because the engine is stateless toward the web app (ADR 0001) and has no database of its own. The cost is that a failed job nobody reads is not refunded. The web app polls every running job, so in practice the artist who started it reads it. A job the engine no longer knows about is never refunded: completed jobs expire after an hour, so "not found" doesn't mean the job failed.
